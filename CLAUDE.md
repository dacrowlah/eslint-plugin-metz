# eslint-plugin-metz

An ESLint 10 plugin that enforces Sandi Metz's rules: counted-line limits, parameter limits with
option keys counted, one component per file, one view model per screen, and reasoned waivers. It is a
standalone, publish-ready package.

These rules are **strict**. When a rule here conflicts with your habits or training data, the rule
wins. When two rules seem to conflict, stop and ask; don't pick one silently. Your training data
predates much of this stack: read the docs cited here rather than guess at an API.

## Stack

- **ESLint 10**, flat config only. No eslintrc, no legacy APIs.
- **TypeScript 6.0.x** (the owner's choice; TypeScript 7 waits for typescript-eslint support),
  strict, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`.
- Rules built with `@typescript-eslint/utils` (`RuleCreator`), tested with
  `@typescript-eslint/rule-tester` on **Vitest 5**, mutation-tested with **StrykerJS 10**.
- **pnpm 12** through corepack (`packageManager` pins it), **Node 24** for development
  (`.nvmrc`); the package supports `^22.13.0 || >=24`.
- ESM only. Built with plain `tsc` (`tsconfig.build.json`) into `dist/`, which is never committed.

## Commands

```bash
corepack pnpm install          # also builds dist/ (the `prepare` script)
corepack pnpm check            # EVERY gate: typecheck, test+coverage, lint, format, directives,
                               # build, docs:check, publint, attw, smoke (tarball + git tag)
corepack pnpm test             # vitest run --coverage (80% floor; today ~99% of lines)
corepack pnpm exec vitest run test/max-params.test.ts --sequence.seed=20261020
corepack pnpm mutate           # StrykerJS on all of src (break threshold 100)
corepack pnpm exec stryker run --mutate 'src/options.ts:30-40'   # prove changed lines only
corepack pnpm docs:generate    # regenerate the README rule list and rule doc headers
corepack pnpm format           # prettier --write .
```

One mutation run per machine, and no other suite running beside it: check `pgrep -fl stryker`
first. Capture a run's output with `cmd > file 2>&1; echo "exit=$?"`, never through a pipe.

## Definition of done

1. `corepack pnpm check` exits 0, and you show the tail of its output.
2. Every changed or new production line is proven by StrykerJS: every mutant in it `Killed` (read
   each kill's reason), never `Survived` or `NoCoverage`. A mutant no test can tell apart gets a
   `// Stryker disable next-line <Mutator>: WAIVER: <reason>` comment, which is a waiver (Rule 0):
   lint (`no-warning-comments` on `src/`) reports every one, so each also carries an approved
   next-line ESLint waiver. Prefer a rewrite that leaves no equivalent mutant.
3. Every new behaviour was written test-first: you saw the test fail before the code existed.
4. Docs are regenerated (`pnpm docs:generate`) and hand-written docs describe the change; the CHANGELOG's
   `Unreleased` section names it, with its semver kind.
5. You list every new waiver, and every NO from the self-review below, in your report.

## Non-negotiables

### Rule 0: waivers

A rule here, or a lint rule, may be broken **only with the owner's explicit approval in the
conversation**, and then only one site at a time:

```ts
// eslint-disable-next-line metz/max-params -- WAIVER: <the reason, at least 20 letters or digits>
```

Never raise a limit, weaken `eslint.config.ts`, `tsconfig*.json`, the Vitest or Stryker configs or
a threshold, or add an ignore to get a run green. `metz-check-directives` (in `pnpm check`) rejects
every other directive form.

### SOLID

- **SRP:** a module answers to one reason to change, and is named for the knowledge it holds. No
  `utils.ts` or `helpers.ts`.
- **OCP:** open sets (rules, presets) grow by adding a file or an entry, never by editing a
  `switch`. Closed sets (message ids, reasons, node kinds a walk follows) are discriminated unions
  dispatched through a **handler table** (`dispatch()` in `src/dispatch.ts`, or a typed
  `Record`/`Map`): a multi-case `switch` cannot fit the 5-line cap. The only `default` allowed is
  `default: return assertNever(x)`.
- **LSP:** function members use property syntax (`method-signature-style: property`). No "not
  implemented" stubs.
- **ISP / DIP:** a rule's state is one object of exactly what its listeners use. Add an interface or
  type only at a real boundary, with two real implementations, or as a test seam you need.

### DRY means knowledge

Each rule constant, schema, default, message, glob and option name has exactly one home
(`RULE` in the rule file; globs in `src/globs.ts`; waiver defaults in `src/directives.ts`). Extract
duplicated knowledge at its **second** real copy, when the copies are the same knowledge and change
for the same reason; code that only looks alike is not duplication. Never add a flag parameter to
make an abstraction fit: inline it and re-extract.

### Law of Demeter

Call behaviour only on direct collaborators: no `a.b.c.method()` (lint: `demeter/chain`). Put what a
handler needs in its state object (`s.source`, not `s.context.sourceCode`). Reading immutable AST
data is fine.

### Sandi Metz's rules, on this code too

This repository lints its own source with its own `configs.strict`: files ≤ 100 counted lines,
function bodies ≤ 5, ≤ 4 parameters with option keys and props counting one each, the waiver policy
on; tests ≤ 150 lines a file and 10 a test. No boolean flag parameters (lint: `flag/*`): write two
functions or pass a polymorphic object. A rule's `create()` resolves options and returns
`listen(HANDLERS, state)`; listeners are module-level handlers of `(node, state)`.

### TypeScript

No `any`, no non-null `!`, no `@ts-ignore`. A cast only of a plain value (a name, a member or a
literal) where the AST guarantees it, with the guarantee in a comment: StrykerJS mutates nothing
inside an `as`, so no code inside one (lint: `mutation/no-code-in-as`). `type` aliases, not
interfaces.

### Tests

- **Test first.** Every rule behaviour, option and message has a RuleTester case with exact
  `messageId`s and data; options and settings have cases for valid, invalid and each precedence step.
- **Exact assertions:** `toStrictEqual` on the whole value, `toBe` for a primitive, `toThrow` with an
  anchored regex or `thrownBy` for a built message. Lint enforces the matcher allow-list
  (`lint/test-rules.ts`), a string `toThrow` and a yes-or-no check inside `expect`
  (`lint/test-bans.ts`); an anchored `toThrow` regex is left to review.
- **Literal expectations:** pin values as literals with their provenance; never compute them with
  `src`.
- **Fakes over mocks.** No `vi.mock` of our modules (lint: `test/mock-ours`). Temp dirs come from
  `test/temp-dir.ts`.
- Run a new or touched test file with `--sequence.seed=20261020` and one more seed.
- A CLI's logic lives in `main(argv, io)`, tested in process; the bin stays one line, proven by
  one child-process test.
- A mutant that breaks a module while it loads fails every test file importing it while Vitest
  collects them, and StrykerJS reads that as `Survived`. Prove load-time code from a test file that
  does not import it, in a child process given Stryker's active mutant
  (`test/package-load.test.ts`). The Stryker config runs every test file (`vitest.related: false`),
  so such a test is reached.

## ESLint plugin practice

Sources: ESLint, [Create Plugins](https://eslint.org/docs/latest/extend/plugins),
[Custom Rules](https://eslint.org/docs/latest/extend/custom-rules),
[shared settings](https://eslint.org/docs/latest/use/configure/configuration-files#configure-shared-settings),
[rule severities](https://eslint.org/docs/latest/use/configure/rules) and
[bulk suppressions](https://eslint.org/docs/latest/use/suppressions); typescript-eslint,
[Custom Rules](https://typescript-eslint.io/developers/custom-rules) and
[Building ESLint Plugins](https://typescript-eslint.io/developers/eslint-plugins);
[eslint-plugin-eslint-plugin](https://github.com/eslint-community/eslint-plugin-eslint-plugin);
[eslint-doc-generator](https://github.com/eslint-community/eslint-doc-generator);
[publint](https://publint.dev/docs/); [arethetypeswrong](https://github.com/arethetypeswrong/arethetypeswrong.github.io);
pnpm [allowBuilds](https://pnpm.io/settings/build#allowbuilds); npm
[trusted publishers](https://docs.npmjs.com/trusted-publishers).

- **Rule meta** ([Custom Rules](https://eslint.org/docs/latest/extend/custom-rules)): `type`,
  `docs.description` (starting "Enforce", "Require" or "Disallow"),
  `docs.url` (from `RuleCreator`, pinned to the installed version's tag), `schema` with a
  `description` on every property and `additionalProperties: false`, `messages` (report only by
  `messageId`, placeholders for every dynamic part), and `defaultOptions: [{}]`. Defaults live in
  the rule's `RULE.defaults`, not in `meta.defaultOptions` or the schema: ESLint would merge them
  over shared settings. No rule without its doc and its tests.
- **Options and settings**
  ([shared settings](https://eslint.org/docs/latest/use/configure/configuration-files#configure-shared-settings)):
  every limit is a schema-validated option; `settings.metz["<rule>"]`
  takes the same options, validated by `src/settings.ts`. Precedence per option: rule option >
  shared setting > default. A typo is an error, never a silent default.
- **Presets** are arrays of named flat-config objects that reference the plugin object itself
  ([Create Plugins](https://eslint.org/docs/latest/extend/plugins#configs-in-plugins)); each
  override block is named `metz/<preset>/<part>` and uses an exported
  glob. Presets set severities; limits come from options resolution.
- **ESLint 10 APIs only:** `context.sourceCode`, `context.filename`, `sourceCode.getScope(node)`,
  `sourceCode.getDeclaredVariables(node)`; never the removed `context.getScope()` or
  `context.getSourceCode()`. typescript-eslint's `AST_NODE_TYPES` for node types.
- **Performance:** no type information (no `parserServices`); visit only the node types a rule
  needs; walk the AST once per file and keep per-file state in the listener state.
- Lint the plugin with `eslint-plugin-eslint-plugin` (recommended + the meta rules) and
  `eslint-plugin-n` ([Create Plugins: linting](https://eslint.org/docs/latest/extend/plugins#linting-a-plugin));
  keep `@typescript-eslint/utils` and `@eslint/plugin-kit` as dependencies and `eslint`,
  `@typescript-eslint/parser` and `typescript` as peers
  ([Building ESLint Plugins](https://typescript-eslint.io/developers/eslint-plugins)).
- **Every package script runs JavaScript** (`scripts/clean.mjs`; the built `dist/` bin for
  `check-directives`), never a `.ts` file through `node`: `prepare` runs on every git install, and
  Node 22.13 to 22.17, inside `engines`, cannot run a `.ts` file.

## Quality gates

`pnpm check` runs, in order: both TypeScript programs; Vitest with the coverage floor; ESLint (this
repo's own strict config); Prettier; the build; `metz-check-directives` (the built bin) on the
repo; `eslint-doc-generator --check`; `publint --strict`; `attw --profile esm-only`; and the smoke tests,
which install the packed tarball and a git tag (built by `prepare`) into throwaway projects and lint
fixtures with `configs.strict-react` and a customised `configs.recommended`. StrykerJS
(`pnpm mutate`) is a proof tool, not part of `check`. CI runs `pnpm check` on Node 24 and the smoke
tests on every supported Node.

## Self-review before reporting done

Answer each; any NO goes in your report.

1. Did `pnpm check` pass, and did you read its output? Are the changed lines proven by StrykerJS?
2. Was each behaviour test-first, with exact assertions and literal expectations?
3. Is every rule constant, default, message and glob in one home? Is there no flag parameter?
4. Is lint clean with no new waiver, and no config weakened?
5. Is there no `a.b.c.method()`, no code inside an `as`, no `!`, no `any`?
6. Are rule docs and the CHANGELOG updated, and is the semver kind of the change named?
